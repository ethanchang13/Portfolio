Little Bird Toys — Toy Company Site

A fully responsive e-commerce site for a fictional handcrafted wooden-toy company — homepage, product catalog, shopping cart, about, and contact, all under one consistent brand.

Year: Junior Type: Multi-page e-commerce site Role: Group / collaborative build
Visit the live site ↗ View on GitHub ↗

What it is

Little Bird Toys is a fictional handcrafted-wooden-toy shop, built out as a real five-page e-commerce experience. The homepage introduces the brand, the products page lists the catalog with filtering and sorting, the cart page handles add / remove / update with live order summaries, and about + contact pages round out the site like a real small business.

Pages

  • index.html — homepage with featured products and hero.
  • products.html — full catalog with filter + sort.
  • cart.html — shopping cart with quantity controls and order totals.
  • about.html — brand story and CTA back to the shop.
  • contact.html — contact form and information.

Tech stack

  • HTML5
  • CSS3 (component-based)
  • JavaScript (ES6+)
  • Bootstrap 5
  • Font Awesome 6
  • GitHub Pages

Highlights

Real shopping-cart state

The cart actually works — add items, change quantities, remove items, and watch the order summary recalculate in real time. First project where I shipped genuine app-style state, not just styled pages.

Component-based CSS

Stylesheets are split into components/ and utilities/ folders so every page reuses the same building blocks instead of re-styling from scratch.

Responsive across every device

Mobile, tablet, and desktop layouts all work with no separate markup — Bootstrap 5's grid plus custom breakpoints.

Accessibility-first

Semantic HTML and ARIA attributes throughout so the site reads properly in a screen reader, not just visually.

What I learned

  • How to architect a multi-page product site so every page feels like the same product, not five separate ones.
  • Real client-side state management — cart contents, quantity changes, totals — without a framework.
  • Why splitting CSS into reusable components pays off the moment you add a second page.
  • Collaborative GitHub workflow: branches, pull requests, and merging features into one cohesive build.
